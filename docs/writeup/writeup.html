Figure 1 — The extension is a TrueForge client; editor capabilities are MCP tools that TrueForge calls. The extension never calls a model provider.
  • Client, not loop. Sessions and turns go through the TypeScript SDK (sessions.create, createTurnStream), and approvals are answered with createTurnEvents. Inline edit and agent mode each have their own session (a new turn cancels a running one). Sessions use an inline AgentSpec built from agents/*.agent.json, which lets sessions.update switch the model in place.
  • Editor capabilities as MCP tools. A Streamable-HTTP MCP server on 127.0.0.1, behind a random bearer token, is registered per workspace and removed on exit. Write tools (propose_edit, propose_new_file, run_command) are in require_approval_for_tools.
  • Approval drives the review. On tool.approval_required, ForgePilot rebuilds the call from the streamed deltas and runs hard checks: each anchor matches exactly once, the Python result parses, and imported repo symbols exist. A failed check is denied back to the agent with the reason and the nearest matching text. Otherwise the edit opens as a per-hunk review, and allow is sent once every hunk has a decision. The MCP handler writes only accepted hunks, in one write, and refuses any call that did not pass review.
  • Harness features.
    • Dynamic sub-agents: one read-only scout maps where similar features are implemented, tested and documented. Writes from sub-agent threads are denied.
    • Deferred tool loading: only reviewed tools are preloaded.
    • Compaction: triggers at 40k tokens.
    • Disabled: ask-user and generative-UI tools, which the panel never renders.

Figure 2 — TrueForge's tool approval gates the hunk review; nothing reaches disk before a decision, and impossible edits never reach the user.

Resilience (Task C). TrueForge has no built-in model fallback, so ForgePilot classifies each failure:

  • Transient (network, 5xx, timeout): exponential backoff.
  • Per-minute rate limit: waits the provider's suggested delay.
  • Permanent (bad key, unknown model, daily quota): not retried.

It then calls sessions.update to move the same session to the next model, keeping history. If edits were already applied, it continues rather than replays. Cancel aborts locally, calls sessions.cancel, discards open reviews and kills agent commands, because TrueForge waits for in-flight MCP calls.

Figure 3 — Retrieval pipeline. Supporting signals explain choices and add files; they never reorder BM25.

Each agent request starts with an automatic pointer pack: up to 20 paths with evidence, ~500 tokens. retrieve_context returns code within the budget (default 6,000 tokens), and @-mentions are always included. The Context Inspector shows every chosen file with its evidence badges and token cost, the budget bar, and what was left out and why. Low-confidence results are flagged.

Why a budget. More retrieved context lowered SWE-bench resolution as recall rose. Chroma's Context Rot shows focused prompts beating long ones on all 18 models tested. Agent Retrieval Bench (arXiv:2607.24882) finds no retrieval family dominates.

Measured trade-off (Flask 3.1.3, 38 queries with grep-labelled gold files):

  • A weighted-fusion ranker beat BM25 on its dev set (MRR 0.71 vs 0.54) but lost on held-out queries (0.54 vs 0.78). It overfit, so we reverted to BM25 ordering.
  • Shipped: 100% recall of the files to change on dev, held-out and a fresh validation set, using ~2% of the repo's tokens.
  • For Task B, the companions bring tests/test_cli.py and docs/cli.rst alongside src/flask/cli.py.

8. Known limitations and the next month

Limitations: static checks are Python-only; ranking equals BM25 (38 queries, one repository); through TrueForge's OpenAI-compatible path Groq rejects echoed reasoning history, so Groq reasoning models served inline edit only; a slow third-party MCP tool can delay TrueForge's cancel.

Next month: tree-sitter checks for more languages; a multi-repo retrieval benchmark; running tests on a shadow copy before acceptance; upstream fixes to TrueForge (native model fallback, listed as planned in its docs, and the reasoning-history issue).
